# 감관법(감정평가관계법규) 문항 제작·검수 흐름

민법 흐름([content-workflow.md](content-workflow.md))과 같지만 **법령 과목이라 AI 오류 위험이 훨씬 크다.**
건폐율·용적률·기간·금액 같은 수치와 조문 번호는 그럴듯하게 틀리기 쉽고, 법령은 자주 개정된다.
그래서 모든 문항은 `reviewed: false`로 들어오고, **사용자가 국가법령정보센터(law.go.kr) 현행 조문과 직접 대조한 뒤에만** `npm run mark`로 검수 완료 표시한다.

```
① 법률별 생성 (Claude 세션) → ② npm run validate -- --strict → ③ 검수 시트로 조문 대조 → ④ npm run mark → ⑤ 빌드·배포
```

## 파일·설정

| 파일 | 내용 |
|---|---|
| `src/data/sets/law-<연도>-<번호>.json` | 감관법 세트 (예: `law-2026-001`). 파일 이름은 `law-`로 시작 |
| `config/law/exam.json` | 시험 포맷(40문항·2.5점·과목당 40분·과락 40점), **기준 법령일 `lawAsOf`**, 9개 법률 정식 명칭 |
| `config/law/blueprint.json` | 법률별 문항 수(국토계획법 13 …), 세트마다 ±1 허용 |
| `config/law/length.json` | 유형별 분량 기준 — 실제 시험지 몇 장을 보고 보정 |
| `law-texts/*.json` | 근거 조문 원문(앱 팝업용). [law-texts/README.md](../law-texts/README.md) |

Q-Net 2027년도 시행계획 공고(2026년 11~12월 예상)가 나오면 `config/law/exam.json`의 출제 범위·`scopeVerified`, 문항의 `lawAsOf`를 갱신한다.

## ① 생성 — 법률별로 나눠 요청

한 번에 40문항을 만들지 말고 법률별로 나눈다(정확도·검수 부담). 새 세션에 붙여 넣을 요청 예:

> civil-exam/docs/law-content-workflow.md 의 "작성 규칙"을 지켜 국토계획법 13문항 JSON을 만들어줘.
> 기존 세트(`law-2026-001`)의 쟁점과 겹치지 않게 하고, 번호는 1~13, setId는 `law-2027-001`.
> 끝나면 다른 법률 문항과 합쳐 `src/data/sets/law-2027-001.json` 으로 저장하고 `npm run validate -- --strict` 를 통과시켜줘.

### 작성 규칙

- **창작 문항만** (`source: "original"`). 기출·학원·공단 문항 문장을 옮기지 않는다. 보유한 기출 PDF는 `local-only/`(gitignore)에 두고 쟁점 파악에만 쓴다.
- **발문**: 법률 이름을 앞에 붙인다 — "국토의 계획 및 이용에 관한 법령상 ~에 관한 설명으로 옳은 것은?". 필요하면 끝에 "(조례는 고려하지 않음)", "(다툼이 있는 경우 판례에 따름)". 이런 괄호 단서는 분량에서 빠진다. 부정 발문은 `<u>옳지 않은</u>`.
- **문체**: "~할 수 있다.", "~하여야 한다.", "대통령령으로 정하는 바에 따라" 등 법령 어투. 본문에는 조문 번호를 쓰지 않는다.
- **표 지문**: 건폐율·용적률·지목 부호 같은 표는 발문(stem)에 `<table>`로 넣는다. 허용 태그 `table, caption, thead, tbody, tr, th, td`, 속성은 `colspan`·`rowspan`만.
- **type**: `single`(단일) / `combo`(ㄱㄴㄷㄹ 조합, 발문에 "모두 고른 것은") / `count`(개수, "몇 개") / `case`(사례, 사실관계 + 물음표 발문) / `numeric`(숫자·기간 비교, 발문 1줄).
- **pattern**(문항 유형 필터): `정의` / `숫자·기간` / `절차·순서` / `예외·단서` / `사례` 중 하나.
- **legalBasis**: 모든 문항에 1개 이상. `{ "instrument": "법"|"시행령"|"시행규칙"|"고시", "cite": "국토의 계획 및 이용에 관한 법률 시행령 제84조 제1항" }` — cite는 **정식 법령명 + 시행령/시행규칙 + 제○조(의○) + 항·호**. 이 형식이어야 조문 팝업·조문 검색이 동작한다.
- **lawAsOf**: 기준 법령일(`config/law/exam.json`의 값).
- **volatile**: 수치·기간·비율·금액이 들어 있으면 `true`(해설에 '개정 확인 필요' 배지). 검증 스크립트가 숫자가 있는데 false면 경고한다.
- **해설 끝맺음**: 복수 정답 자동 검사를 위해 보기별 해설의 끝을 맞춘다 — 정답 보기는 "… 정답.", "옳지 않은 것" 문항의 나머지 보기는 "… 옳다.", "옳은 것" 문항의 나머지 보기는 틀린 이유만 쓰고 "옳다"로 끝내지 않는다.
- **정답 번호**: ①~⑤ 각 8개 안팎, **법률별 배분**은 blueprint ±1.
- **분량**(`config/law/length.json`): 단일형 발문 25~60자·보기 50~160자·전체 350~850자 / 조합·개수형 박스 항목 60~150자·전체 450~800자 / 사례형 사실관계 150~350자·보기 50~140자·전체 550~950자 / 숫자형 보기 40~100자·전체 300~600자.
- **난이도**: 도시정비법은 난이도 3 비율을 높게. 국토계획법은 지문이 길고 범위를 고르게(용도지역·지구·구역, 건폐율·용적률, 기반시설, 도시·군관리계획, 개발행위허가, 지구단위계획).
- **현행 여부가 불확실한 조문**(최근 개정·시행 예정)은 출제하지 않는다. 예: 국토계획법의 공간재구조화계획·도시혁신구역 등 최근 신설 제도는 시행일을 확인한 뒤에만.

## ② 자동 검증

```bash
npm run validate -- --strict src/data/sets/law-2027-001.json
```

감관법 추가 검사: `subject`·`law`·`pattern`, **legalBasis 누락(오류)**, instrument와 cite 표기 불일치, 조문 번호 없음, **lawAsOf 누락·형식(오류)**, 숫자가 있는데 `volatile: false`, 발문에 법률 이름 없음, 표 태그 짝·속성, **복수 정답 의심**(묻는 쪽으로 판정된 보기 해설이 2개 이상), 40문항 세트의 법률별 배분(blueprint ±1), 세트 안 기준 법령일 불일치. 전체 실행 시 끝에 "감관법 문항 풀" 법률별 충족 현황(맞춤 모의고사용)이 나온다.

## ③ 검수 (사람) — 조문 대조가 핵심

```bash
npm run review-sheet -- law-2027-001     # docs/review/law-2027-001.md
```

문항마다:

1. 정답이 하나뿐인가 (다른 보기도 옳다/틀리다고 다툴 여지가 없는가)
2. 근거 조문 체크박스마다 law.go.kr에서 **조문 번호와 내용**을 열어 대조 — 법인지 시행령인지 시행규칙인지까지
3. 수치·기간·비율·금액이 기준일 현행 법령과 같은가 (⚠ 개정 위험 문항은 특히)
4. 시험 공고일 전에 시행되는 개정이 있는가 (law.go.kr '연혁'·'시행예정' 확인)

조문 원문을 `law-texts/`에 넣어 두면 앱에서도 해설 → 근거 조문을 눌러 바로 대조할 수 있다.

## ④ 검수 표시

```bash
npm run mark -- law-2027-001-q01 law-2027-001-q02   # 검수 완료 → 앱의 '미검수'·'조문 확인 필요' 배지가 사라짐
npm run mark -- law-2027-001-q01 --undo
```

## 법령이 개정되면

1. 앱 **설정 → 조문으로 찾기**에 개정 조문(예: `국토계획법 시행령 제84조`)을 넣어 영향받는 문항을 찾는다 (약칭·공백 무시, `제84조`로 찾으면 `제84조의2`는 제외).
2. 해당 문항을 고치고 `lawAsOf`를 새 기준일로, `reviewed: false`로 되돌린 뒤 ②~④를 다시 한다.
3. `law-texts/`의 조문도 갱신한다(`npm run fetch-law`).
