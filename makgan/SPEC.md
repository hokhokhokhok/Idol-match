## 1. 한 줄 소개
뮤지컬·연극 팬이 **공연·배우·혜택(로터리/할인/티켓오픈)** 을 한곳에서 보고, **찜·팔로우·관극 후기**로 내 관극을 기록하는 모바일 웹앱(PWA).

## 2. 기술 스택
- Next.js(App Router, TypeScript, 서버 액션) + Supabase(Postgres, Auth 매직링크, RLS)
- 배포: Vercel(앱) + Supabase(DB). GitHub Pages(정적)에서는 돌지 않는다.
- 모든 시각 표시는 KST, DB는 `timestamptz` (2부 A-5).

## 3. 화면 구조 (하단 5탭)
| 탭 | 경로 | 내용 |
|---|---|---|
| 홈 | `/` | 오늘 마감 혜택 3 + 곧 열리는 티켓 3 + 내 찜 공연 |
| 공연 | `/shows`, `/shows/[id]` | 목록(상태·극장·배우·기간 필터, 정렬), 상세(캐스팅·평균 별점·후기) |
| 혜택 | `/benefits` | 로터리/할인/티켓오픈/이벤트, 마감 지난 항목 기본 숨김 |
| 배우 | `/actors`, `/actors/[id]` | 목록, 상세(출연작·팔로우) |
| MY | `/me` | 내 관극 후기, 찜, 팔로우, 통계 |

- 상단 🔍 → `/search` (2부 A-4). 관리자 화면 `/admin`(탭에 없음).
- 색: 포인트 버건디, 오늘 마감 배지 주황.

## 4. 데이터 모델 (요약)
`profiles`, `theaters`, `shows`, `actors`, `casts`(날짜별 또는 시즌 캐스팅), `benefits`, `wishlists`, `follows`, `reviews`(관극 후기, 공개/비공개), `seat_reviews`(시야·거리·음향 1~5), `glossary`.
상세 정의는 `supabase/migrations/0001_init.sql`.

### 권한 원칙 (RLS)
- 공연·배우·극장·캐스팅·혜택·용어: 누구나 읽기, 쓰기는 관리자(`profiles.is_admin`)만.
- 찜·팔로우: 본인 행만 읽기/쓰기.
- 관극 후기: 공개 후기 또는 본인 후기만 읽기, 쓰기·수정·삭제는 본인만.
- 좌석 후기: 누구나 읽기, 쓰기·수정·삭제는 본인만.
- `is_admin`은 사용자가 바꿀 수 없다(SQL 편집기에서만 부여).

## 5. 구현 순서 (1~9단계)
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 프로젝트 뼈대: Next.js·Supabase 연결, DB 스키마·RLS, [샘플] 시드, 하단 5탭 레이아웃, KST 날짜 유틸 | 빌드 통과, 5탭 이동, 마이그레이션·RLS 테스트 통과 |
| 2 | 로그인(매직링크)·첫 로그인 닉네임·로그인 필요 안내 | 로그인/로그아웃, 닉네임 저장 |
| 3 | 공연 목록/상세(`listShows`, `getShow`, `getCast`) | 필터·정렬·커서 페이지, 날짜별 캐스팅 |
| 4 | 배우 목록/상세 + 팔로우(`toggleFollow`) | 출연작 표시, 팔로우 토글 |
| 5 | 혜택 목록(`listBenefits`) + 마감 배지 | 마감 지난 항목 숨김, 오늘 마감 주황 배지 |
| 6 | 찜(`toggleWishlist`) | 비로그인 시 로그인 안내 |
| 7 | 홈(`getHome`) | 오늘 마감 3 + 곧 열리는 티켓 3 + 내 찜 |
| 8 | 관극 후기 CRUD + 내 기록(`/me`) | 본인만 수정/삭제, 비공개 후기 보호 |
| 9 | 관리자(`/admin`, 서버에서 `is_admin` 재검증) + 검색 | 관리자 아님 → 홈으로, 서버 액션 거부 |

이후 단계(10~16)는 `SPEC-2.md` C번 표.

## 6. 데이터 원칙
- 실제 극장 좌석 배치, 실제 배우·공연 정보를 임의로 만들지 않는다. 시드·예시 데이터는 이름 앞에 **[샘플]** 을 붙인다.
- 스펙에 없는 기능은 만들기 전에 먼저 제안한다.
