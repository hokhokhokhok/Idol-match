# 조문 암기 트레이너 (감정평가사 2차 「감정평가 및 보상법규」)

조문의 핵심어를 빈칸으로 가리고 직접 떠올려 쓰는 **빈칸 인출 + 등급별 간격 반복** 앱입니다. 아이패드 Safari에서 홈 화면에 추가하면 오프라인에서도 동작합니다. 프레임워크나 빌드 도구 없이 순수 HTML/JS/CSS로 만들었습니다. 기획은 [PLAN.md](PLAN.md)에 있습니다.

> 같은 저장소 루트의 '아이돌 매칭 맵', `civil-exam/`(민법 모의고사)과는 별개 앱입니다. 이 폴더만으로 동작합니다.

**배포 URL:** https://hokhokhokhok.github.io/Idol-match/jomun/ (`main`에 병합하면 GitHub Pages로 배포)

## 아이패드 Safari에서 홈 화면에 추가하기

1. **Safari**로 배포 URL을 엽니다. 크롬 등 다른 브라우저에서는 홈 화면 앱으로 설치되지 않습니다.
2. 주소창 옆 **공유** 버튼(□↑) → **홈 화면에 추가** → 이름 '조문암기' 확인 → **추가**.
3. 홈 화면의 아이콘으로 열면 주소창 없는 전체 화면 앱으로 실행됩니다.
4. **한 번은 인터넷이 될 때 열어야** 앱 파일이 기기에 저장됩니다. 그다음부터는 비행기 모드에서도 열립니다.
5. 주의: 홈 화면 앱과 Safari 탭은 **저장 공간이 따로**입니다. Safari에서 공부한 기록은 홈 화면 앱에 보이지 않으니, 옮기려면 관리 → 백업 파일 저장 → 다른 쪽에서 파일 열기로 복원하세요.
6. iOS는 오랫동안 열지 않은 웹앱의 데이터를 지울 수 있습니다. **백업 파일 저장을 주기적으로** 해 두세요(공유 시트 → '파일에 저장').

## GitHub Pages 배포

이미 저장소에 설정돼 있습니다(`.github/workflows/pages.yml`).

1. 저장소 **Settings → Pages → Source: GitHub Actions**가 선택돼 있는지 확인합니다(한 번만).
2. 이 브랜치를 `main`에 병합하면 워크플로가 단위 테스트(`node --test jomun/tests/*.test.js`)를 통과한 뒤 `jomun/`의 앱 파일(index.html, sw.js, manifest, js/, icons/)을 `/Idol-match/jomun/`에 올립니다.
3. Actions 탭에서 'Deploy to GitHub Pages'가 초록색이면 위 배포 URL에서 열립니다.

모든 경로가 상대 경로라 다른 저장소나 하위 경로에 그대로 올려도 됩니다. 이 폴더만 따로 쓰려면 새 저장소 루트에 `jomun/` 안의 파일을 올리고 Settings → Pages → **Deploy from a branch**(main / root)를 고르면 됩니다. HTTPS 주소여야 서비스 워커(오프라인)가 동작합니다.

**업데이트 배포 시:** 앱 파일을 고쳤다면 `sw.js`의 `VERSION`을 올리세요(예: `"v1"` → `"v2"`). 그래야 이미 설치된 아이패드도 새 파일을 받습니다. 새 버전은 앱을 한 번 열고 닫은 뒤 다시 열면 적용됩니다.

### 하루 10조문
- 하루 목표는 기본 **10조문**입니다(관리 → 하루 조문 수에서 1~200으로 변경). 예전 기본값 30을 그대로 쓰던 기기는 업데이트 후 10으로 바뀌고, 직접 바꾼 값은 유지됩니다.
- '오늘 조문 시작'은 목표에서 오늘 이미 평가한 조문 수를 뺀 만큼만 냅니다. 하루에 여러 번 나눠 해도 합계가 10개입니다('몰랐다' 재출제는 한 조문으로 셈).
- 목표를 채운 뒤에도 대기 중인 조문이 있으면 **'10개 더 하기'**로 더 할 수 있습니다.
- 대기 중인 조문이 목표보다 적으면 홈에 '조문을 더 넣으세요' 안내가 나옵니다. 기본 조문 팩(116개)이 들어 있어 처음부터 매일 10개가 채워집니다.

### 복습 규칙 (PLAN.md 4번)
박스 0~6, 간격 `[1,1,2,4,7,14,30]`일, 실제 간격 = `min(박스 간격, 등급 상한 A2·B4·C7·D14)`. 알았다 +1 / 애매 유지 / 몰랐다 −2 + 세션 내 재출제(다음 날 다시 대기). 정렬: **이미 공부한 조문의 복습 → 처음 보는 조문** 순(조문을 한꺼번에 많이 가져와도 복습이 밀리지 않게), 그 안에서 등급 A → 낮은 박스 → 오래 밀린 것.

오답 노트의 복습도 실제 복습으로 기록됩니다(박스·다음 복습일이 바뀜).

### 등급 점수 계산
조문별로 기출 빈도·답안 필수도·쟁점 연결성·총평 언급·암기 난이도를 0~10점으로 넣으면 가중치 40/30/15/10/5%로 0~100점을 계산하고 80↑A · 60↑B · 40↑C · 그 외 D를 제안합니다. **수락**을 눌러야 등급이 바뀝니다. 입력한 점수는 조문의 `score` 필드에 저장되고 백업·내보내기에 포함됩니다.

### D-day 일일 한도 제안
시험일을 넣으면 `(Σ 1/등급 상한 간격 + 아직 한 번도 안 본 조문 수 / 남은 일수) × 여유 배수`를 5개 단위로 올림해 제안합니다(5~200). 여유 배수: 90일 초과 1.0 · 90일 이내 1.2 · 30일 이내 1.5 · 7일 이내 2.0. 앞부분은 등급 주기대로 전 범위를 돌리는 데 필요한 하루 평균량입니다. **적용**을 눌러야 한도가 바뀝니다. 복습 간격 자체를 압축하지는 않습니다(PLAN.md v3 항목, 아직 안 함).

## 데이터 가져오기 형식

관리 → 텍스트 칸에 붙여넣거나 **파일 열기**로 `.json`을 고른 뒤 **가져오기·복원**.

```json
{
  "items": [
    {"id": "bosang-71-1", "law": "토지보상법", "article": "제71조 제1항", "title": "…", "grade": "B",
     "text": "…{{빈칸}}…", "tags": ["…"], "source": {"exams": ["제33회 1번"], "note": "…"}, "verified": false}
  ],
  "chains": [
    {"id": "loss-comp-req", "title": "손실보상의 요건", "ids": ["…조문 id…", "…", "…"], "note": "", "verified": false}
  ]
}
```

- 조문 배열만 `[ {...}, ... ]` 넣어도 됩니다. 필수: `id`, `law`, `article`, `grade`(A/B/C/D), `text`. 빈칸은 `{{ }}`.
- **`verified`는 `true`일 때만 원문 대조 완료**로 봅니다. 빠지면 `false`로 저장되고 "원문 대조 필요"가 표시됩니다. 앱에서 원문과 대조했다면 관리 → 조문 목록에서 체크하세요.
- 같은 `id`는 내용만 갱신하고 학습 기록(box·due·log)은 유지합니다. 연결 쟁점은 같은 `id`면 통째로 바꿉니다.
- **오류가 하나라도 있으면 아무것도 바꾸지 않고** 오류 목록을 보여 줍니다(예: `조문 2번째 (id: t-2): grade는 A·B·C·D 중 하나여야 합니다 (받은 값: "E")`, 빈칸 괄호 짝, 중복 id, 날짜 형식 등). JSON 문법 오류는 위치(줄·글자)를 함께 알려 줍니다(브라우저가 위치를 알려 줄 때).
- 경고(오류 아님): 빈칸이 없는 조문, `verified`가 true가 아닌 조문, 연결 쟁점이 아직 없는 조문 id를 가리킬 때("미등록"으로 표시).
- **백업 파일**(`{"app":"jomun-trainer","schema":2,"state":{…}}`)을 넣으면 확인 후 **전체 교체(복원)**합니다. 다른 앱 파일이나 더 새 버전 앱의 백업은 거부합니다.
- 내보내기: **백업 파일 저장**(전체 상태, iPad는 공유 시트 → 파일에 저장) / **백업을 텍스트로** / **조문 데이터만**(학습 기록 없이 items+chains — 다른 기기에 조문만 나눌 때).

샘플 조문 3개(토지보상법 제67조 ①②, 제70조 ①)와 샘플 연결 쟁점 1개는 모두 `verified:false`입니다. **국가법령정보센터(law.go.kr) 원문과 대조한 뒤** 쓰세요. 기본 조문 팩도 같은 이유로 모두 `verified:false`입니다(위 참고).

## 데이터 안전

- 학습 상태는 기기의 `localStorage`(키 `jomun-v1`)에 저장합니다. v1에서 쓰던 데이터는 그대로 읽어 새 형식으로 바꿉니다(학습 상태 유지).
- **저장에 실패하면**(공간 부족, 저장소 차단) 화면 위에 주황색 안내가 뜹니다. 그때는 바로 백업 파일을 저장하세요.
- 저장된 데이터가 손상돼 읽지 못하면 샘플로 새로 시작하되, 원본은 `jomun-v1-broken-<시각>` 키에 보관하고 안내합니다.
- 실행 시 브라우저에 영구 저장(`navigator.storage.persist`)을 요청합니다. 관리 화면에 저장 용량과 허용 여부가 나옵니다.

## 폴더 구조

```
jomun/
  index.html            화면과 이벤트(인라인 스크립트)
  js/core.js            순수 로직: 스케줄·기록·오답·등급 점수·D-day·가져오기 검증·마이그레이션 (브라우저·Node 공용)
  sw.js                 서비스 워커(앱 파일 cache-first, VERSION으로 갱신)
  manifest.webmanifest  PWA 매니페스트
  data/pack.js          기본 조문 팩 116개 + 연결 쟁점 8개 (브라우저·Node 공용, 모두 원문 대조 필요)
  icons/                icon.svg(원본, 단색) → icon-192/512, apple-touch-icon(180)
  tests/                node:test 단위 테스트
  scripts/make-icons.mjs  아이콘 PNG 생성(sharp)
  scripts/e2e.mjs       브라우저 자동 점검(Playwright, Chromium)
  PLAN.md               기획안
```

## 개발

저장소 루트에서:

```bash
node --test jomun/tests/*.test.js      # 단위 테스트(의존성 없음) — 파일 하나만: node jomun/tests/schedule.test.js
npm install                            # (아래 두 개에만 필요: playwright, sharp)
node jomun/scripts/e2e.mjs             # iPad 세로·가로, 아이폰 크기 자동 점검 → jomun/screenshots/
node jomun/scripts/make-icons.mjs      # icons/icon.svg를 고친 뒤 PNG 다시 만들기
npm run serve                          # http://localhost:4173/jomun/
```

`index.html`을 파일로 직접 열어도(`file://`) 동작하지만 서비스 워커(오프라인)는 http(s)에서만 켜집니다.

## 이번 변경 요약 (v1 → v1.1/v2 일부)

- v1 코드를 `jomun/`에 그대로 옮긴 뒤, 로직을 `js/core.js`로 분리(동작 같음). 화면 이벤트는 `onclick` 문자열 대신 `data-act` 위임으로 바꿔, id에 따옴표가 있어도 깨지지 않게 함.
- PWA: 매니페스트, 단색 SVG 기반 아이콘 192/512(+maskable)/180, 오프라인 서비스 워커. 루트의 아이돌 앱 서비스 워커가 `/jomun/` 요청을 가로채지 않도록 제외(루트 `sw.js` VERSION v3).
- 오늘 학습 기록(날짜별 복습 수·알았다/애매/몰랐다·정답률), 연속 학습일, 14일 달력.
- 오답 노트(최근 7일 "몰랐다") + 이 조문만/전체 복습.
- 통합 연결 훈련: 데이터에 `chains`(쟁점명 + 조문 id 순서) 추가, 훈련·결과·직접 만들기/수정/삭제, 최근 결과 기록(`chainLog`).
- 등급 점수 계산 화면(제안 → 수락 시 반영, 모두 수락).
- D-day 입력 → 일일 한도 제안·적용.
- (후속) 하루 목표 기본 10조문, 오늘 한 조문 수만큼 차감·'더 하기', 복습 우선 정렬, 본문 빈 조문은 가져오기에서 건너뜀.
- (후속) 기본 조문 팩 116개(토지보상법·부동산공시법·감정평가법·행정기본법·행정소송법·행정절차법·헌법 제23조) + 연결 쟁점 8개 내장, 기존 기기엔 없는 id만 추가.
- iPad: 버튼·입력 48px 이상(문장 속 빈칸은 46px), 입력 글자 16px 이상(확대 방지), 가로·세로 대응, 홈 인디케이터·좌우 안전 영역 여백, 더블탭 확대 방지.
- 데이터 안전: 저장 실패 안내, 손상 데이터 보관, 백업 파일 저장(공유 시트)·파일로 복원, 가져오기 스키마 검증(전부 아니면 전무)과 위치가 담긴 오류 메시지, `verified` 기본 false.
- 단위 테스트 23개(스케줄 박스·간격·등급 상한, 정렬, 날짜, 기록·연속일, 오답, 점수, D-day, 가져오기 검증, 백업 왕복, 마이그레이션).
- 바뀐 점 하나: v1의 '등급 기준' 안내문이 B=격일, C=주 1~2회라고 돼 있던 것을 실제 상한(B 4일, C 7일)에 맞춰 고침.

## 실기기 체크리스트 (아이패드 Safari)

자동 점검은 Chromium에 iPad 크기·UA를 준 것이라, 아래는 실제 기기에서 확인해야 합니다.

- [ ] 홈 화면에 추가 → 아이콘·이름 '조문암기' → 전체 화면 실행
- [ ] 비행기 모드에서 홈 화면 앱 실행
- [ ] 빈칸 입력 시 화면이 확대되지 않음, 한글 입력 중 키보드 '다음'으로 다음 칸 이동
- [ ] 가로/세로 회전 시 레이아웃, 홈 인디케이터에 하단 버튼이 가리지 않음
- [ ] 백업 파일 저장 → 공유 시트 → 파일에 저장 → 관리 → 파일 열기로 복원
- [ ] 날짜 선택(시험일) 휠이 정상 동작
